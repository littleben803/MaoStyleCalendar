# 视觉偏差复核

范围：当前用户明确重新提供的七张静态原稿，对照被否决的 v1 归档稿。不是运行中 App 的流程审计，不推断手势、滚动、触控和无障碍已经通过。

## 原因

v1 使用一套新绘图参数重新设计了界面，而非忠实还原：把候选字体的基线字号当作最终视觉参数，把重新生成的插画与铜环当作原稿替代，把“文字无溢出/颜色对比度合格”误当作“视觉还原合格”。这些检查不能证明构图、字重、材质或细节一致。

## 还原时必须对照的层

1. 结构：标题位置、卡片外框、叠页厚度、操作条、Tab 和购买区。
2. 排版：日号字重/字面占比，语录方向、列宽与行距，日期主次，标题字号与中英文换行。
3. 图片：人物和山水占比、焦点位置、边缘与纸面融合；不换一幅构图再称已还原。
4. 材质：米白纸纤维、朱红印刷纹理、铜环高光与暗面、中缝/边缘投影。
5. 微细节：红短线、红竖标、圆形关闭、按钮箭头、选中圆点、胶囊描边、分隔线、图标线宽。

必须将同一页面、同一尺寸、同一示例文本的还原稿与原稿并排或叠加检查。原稿里的日期/文案变更作为明确例外记录，不能用于解释其余构图漂移。原稿与重建稿差异仍明显时不能宣布完成，不能再以批量导出数量、文件散列或不溢出替代视觉验收。

## 截图不能证明的项目

实际触控尺寸、VoiceOver、动态字号、动画与滚动需要 SwiftUI/WidgetKit 实测；不能按截图图标尺寸推断命中区。保留至少 44×44 pt 的触控区域要求，但实际实现不能为了命中区改变图标本身的视觉大小。系统着色的实际输出不在这七张浅色/英文原稿中，不能宣称已重新验证。
